By default, this cloud uses no-delay provisioning: as soon as a task enters the queue and no executor is free, a new agent is started immediately instead of waiting for the standard Jenkins provisioning strategy. This gives the shortest queue time, but it can start extra VMs when an executor is about to become free, for example between consecutive node blocks of a Pipeline.

Select this option to use the standard Jenkins provisioning strategy for this cloud instead. Jenkins then waits briefly to see whether queued tasks can be served by existing executors before provisioning new agents. This avoids extra VMs, but jobs may wait longer for an agent to start.

The system property com.microsoft.azure.vmagent.AzureVMNoDelayProvisionerStrategy.disableNoDelayProvisioning=true disables no-delay provisioning for all clouds and takes precedence over this option.
